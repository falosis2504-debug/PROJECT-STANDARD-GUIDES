# 07. 프로젝트 킥오프 체크리스트

- 상태: **확정** | 버전: 1.2
- 선행: 00~06, 02-1~02-3, 08

## 목표
신규 프로젝트에 이 표준 문서 세트를 적용하는 절차와 점검 항목을 정리한다.
- **🔒 고정 규칙**은 그대로 적용하고, **✏️ 가변 항목**만 프로젝트별로 정의한다.

## 1. 적용 절차 (4단계)
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| A. 사전 준비 | 계정·권한·저장소·도구 준비 (2장) | 필수 계정과 저장소, GitLab 설정 완료 |
| B. 표준 확정 | 업무 분석 후 ✏️ 가변 항목 정의 (3장) | 3장 표의 모든 항목에 값이 채워짐 |
| C. 환경 구성 | 저장소 기본 파일, CI/CD, 린터, 산출물 폴더 구성 (4장) | 샘플 MR 이 파이프라인을 통과 |
| D. 공유·교육 | 팀 교육, 온보딩, 표준 버전 확정 (5장) | 확정 태그 부여, 전원 숙지 확인 |

## 2. A. 사전 준비
### 2.1 계정 · 권한 🔒
- [ ] **프로젝트 생성 계정** 확정 — 이 계정이 **운영 배포 승인자**이며 **롤백 결정자**이다. (05 6.1·6.3)
- [ ] **관리자 계정** 확정 — `main`·`stage`·`develop` 직접 push 가능한 유일한 계정. 개발자 계정은 직접 push 불가. (05 2.2)
- [ ] 개발자 계정 권한: `develop`·`stage` MR 병합 가능, `main` 병합 불가
- [ ] 표준 관리자(00) 지정 — 표준 작성·변경 승인 담당

### 2.2 저장소 · 도구 🔒
- [ ] **프론트엔드·백엔드 저장소 분리** 생성 (05 1장), 저장소 이름 정의 ✏️
- [ ] 표준 문서(`docs/`) 위치 결정 — 별도 표준 저장소 / 한쪽 저장소 + 링크 [결정 필요, 05 1장]
- [ ] GitLab 브랜치 생성: `main`, `stage`, `develop`
- [ ] GitLab 브랜치 보호 설정 (05 2.2): `main`·`stage`·`develop` 직접 push 는 관리자만, force push·삭제 금지, `main` 병합은 승인 필수
- [ ] 병합 방식 **Merge commit 전용** 설정, CI 통과를 병합 조건으로 설정 (05 4장)
- [ ] 도커 서버(dev·stg·prod) 접근과 배포 계정 준비, **GitLab CI/CD**(기본) 또는 Jenkins 선택 (05 7장)
- [ ] CI 시크릿 저장소에 배포 자격증명 등록 (03 5.4)
- [ ] 이슈 라벨 생성: `feature`, `bug`, `change`, `docs`, `chore`, 우선순위 `P1`~`P4` (05 8장)

## 4. C. 환경 구성 체크리스트
### 4.1 저장소 기본 파일 🔒 (프론트·백엔드 각각)
- [ ] `README`, `.gitignore`(시크릿·빌드 산출물·로컬 설정 제외), `.editorconfig`(UTF-8, LF, 스페이스 4칸, 줄 길이 120)
- [ ] MR(PR) 템플릿 (05 4장), 이슈 템플릿
- [ ] 파이프라인 정의 파일(GitLab CI/CD 또는 Jenkins) 커밋
- [ ] 포매터·린터 설정 파일: BE `Spotless`·`Checkstyle`(설정 XML), FE `Prettier`·`ESLint` (03 1장, 8장)
- [ ] DB 스크립트 폴더와 마이그레이션 규칙 `V{버전}__{설명}.sql` (백엔드, 04 2.1)
- [ ] 폴더 구조: 기능코드 폴더(`CM` 포함) + 역할 접미사 폴더 생성 (02 5.7)

### 4.2 CI/CD · 품질 게이트 (05 7장, 06 7장)
- [ ] 1.빌드 → 2.린트 → 3.단위 테스트 → 4.**Semgrep** 정적분석·시크릿 검사 단계를 MR 파이프라인에 구성
- [ ] **G1** 통과 조건 설정: 빌드·린트·단위 테스트 통과, Semgrep ERROR(High) 이상 0건, 시크릿 검출 0건
- [ ] dev·stg **반자동 배포** 구성: 병합 후 개발자가 배포 시작 버튼 → 빌드 → 도커 서버 배포·재기동
- [ ] prod 배포: `main` 태그 + 운영 배포 승인자 승인 후 수동 배포
- [ ] 샘플 MR 로 파이프라인 동작 확인 (`feature` → `develop` → `stage` → `main`)

### 4.3 공통 구현물 🔒
- [ ] 공통 응답 포맷(`success`, `code`, `message`, `traceId`, `data`, `exception`) 구현 (04 3.1)
- [ ] 업무 예외 처리기: `exception` 구조·`errors[]` 생성, `rejectedValue` 민감정보 마스킹 (04 3.1.1)
- [ ] 시스템 오류 처리기: `E`+순번 에러 코드 부여, 내부 정보 비노출 (03 3.3)

- [ ] Trace ID 생성·전파, 로깅 설정(레벨·마스킹·Trace ID·프로그램 ID) (03 4장)
- [ ] 로그 수집: 앱 서버 `/logs/{시스템코드}/{환경}/`, 중앙 로그 서버 전송, 로테이션·보관 (03 4.3)
- [ ] 세션 기반 인증·서버측 인가 검사 기본 구현 (04 3.3, 03 5.2)
- [ ] Springdoc OpenAPI(Swagger UI) 구성, **prod 프로파일에서 비활성화** 확인 (04 3.3, 03 8.2)
- [ ] MyBatis 설정(`resources/mapper/{기능코드}/`, `map-underscore-to-camel-case`, 공통 TypeHandler) (03 8.2)
- [ ] FE `package-lock.json` 커밋, TanStack Query·Zustand·React Router 기본 구성(`stores`·`routes`) (03 8.3)
- [ ] 감사 컬럼 6개 공통 처리, 공통코드 테이블(`TB_CM_CD_GRP_C`, `TB_CM_CD_DTL_C`) (02-1, 04 4장)
