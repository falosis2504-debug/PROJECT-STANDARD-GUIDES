# 08. 산출물 구조

- 상태: **확정** | 버전: 1.1
- 🔒 고정(폴더 체계) / ✏️ 가변(업무 폴더 = 기능코드별)

## 목적
SI 프로젝트 산출물을 단계별로 보관하는 표준 폴더 구조이다. 이 `docs/` 의 표준 문서는 `02_설계/01_공통표준_아키텍처` 에 해당한다.
산출물은 개발 문서(`docs/`)와 **별개의 관리 문서**이며 **공유 폴더**에서 관리한다. 위치는 프로젝트 진행자가 별도로 생성한다.

## 1. 폴더 구조
```
[프로젝트명]_산출물/
├── 00_프로젝트관리/
│   ├── 01_착수_계획/              # 사업수행계획서, WBS, 인력투입계획서, 보안서약서
│   ├── 02_진척_보고/              # 주간/월간보고서, 공정률관리, 회의록
│   ├── 03_위험_이슈_변경/         # 위험관리대장, 이슈관리대장, 요구사항변경요청서(CR)
│   └── 04_품질_감리/              # 품질보증계획서, 감리수검자료, 시정조치결과서
│
├── 01_분석/
│   ├── 01_요구사항관리/           # 요구사항정의서, 요구사항추적표(RTM)
│   ├── 02_현행시스템분석/         # 현행업무(As-Is)분석서, 현행시스템구성도
│   └── 03_프로세스_화면분석/      # 업무프로세스정의서(To-Be), 화면목록, 메뉴구조도(IA)
│
├── 02_설계/
│   ├── 01_공통표준_아키텍처/      # 시스템아키텍처정의서(SA), 개발표준정의서, 명명규칙정의서
│   ├── 02_데이터_DB설계/          # 데이터표준화정의서(단어/용어/도메인), ERD(논리/물리), 테이블정의서, 코드정의서
│   ├── 03_인터페이스_전문설계/    # 인터페이스목록, 전문정의서(EAI/FEP/대외계), 매핑정의서
│   ├── 04_화면_프로그램설계/
│   │   └── {기능코드}_{업무명}/   # 업무(기능)별: 화면설계서(SB), 배치설계서, 프로그램목록  ✏️
│   └── 05_인프라_보안설계/        # H/W·N/W구성도, 보안아키텍처, 개인정보영향평가, 보안성심의자료
│
├── 03_개발/
│   ├── 01_DB_스크립트/            # DDL(테이블/인덱스/시퀀스/코멘트), DML(초기코드/기준데이터)
│   ├── 02_단위테스트/
│   │   └── {기능코드}_{업무명}/   # 단위테스트케이스(UTC), 단위테스트결과서  ✏️
│   └── 03_코드인스펙션/           # 정적분석결과서(시큐어코딩), 소스코드점검결과서
│
├── 04_테스트/
│   ├── 01_통합테스트/
│   │   ├── {기능코드}_{업무명}/   # 통합테스트시나리오(ITC), 통합테스트결과서  ✏️
│   │   └── 99_결함관리대장/       # 통합테스트 결함관리대장
│   ├── 02_성능_부하테스트/        # 성능테스트계획서, 스트레스/부하테스트결과서, SQL튜닝결과서
│   ├── 03_사용자_인수테스트/      # 인수테스트시나리오(UAT), 현업인수확인서
│   └── 04_대외_연계테스트/        # 대외기관 연계테스트결과서
│
├── 05_데이터전환_이행/
│   ├── 01_데이터전환_이관/        # 데이터전환계획서(원장이행), 매핑정의서, 전환검증결과서
│   ├── 02_시스템이행_오픈/        # 시스템이행계획서(Cut-Over), 리허설결과서, 비상대응계획(BCP)
│   └── 03_교육_매뉴얼/            # 사용자매뉴얼, 운영자매뉴얼(IT운영팀용), 교육결과서
│
└── 06_종료/
    ├── 01_검수_완료/              # 최종산출물목록, 사업완료보고서, 검수요청서
    └── 02_운영이관/               # 운영이관합의서(SM인수인계), 하자보수계획서
```

## 2. 업무 폴더 규칙 ✏️
- 업무 폴더명은 `{기능코드}_{업무명}` 으로 한다. (예: `CM_공통`, `IS_투자전략`, `AM_자산관리`) 공통 업무 `CM` 은 필수.
- 업무 폴더는 `04_화면_프로그램설계`, `02_단위테스트`, `01_통합테스트` 하위에 **동일한 목록**으로 둔다.
- 폴더 번호(`00`~`06`, `01`~)는 고정이며 임의 변경·삭제하지 않는다. 해당 없는 폴더도 유지하고 `해당없음` 사유 파일을 둔다.
- 파일명은 `{산출물명}_{업무 또는 대상}_v{버전}.{확장자}` 형식을 권장한다.

## 3. 표준 산출물 ↔ 보관 위치
| 산출물 | 근거 | 보관 위치 |
|---|---|---|
| 개발표준정의서·명명규칙정의서 | 이 `docs/` 문서 세트 | `02_설계/01_공통표준_아키텍처` |
| 데이터표준화정의서(단어/용어/도메인) | 02-1, 02-2 | `02_설계/02_데이터_DB설계` |
| 테이블정의서·컬럼정의서·ERD | 04 2장 | `02_설계/02_데이터_DB설계` |
| 코드정의서(공통코드 그룹·코드 대장) | 04 4장 | `02_설계/02_데이터_DB설계` |
| 인터페이스목록(인터페이스 대장) | 02-3 6장 | `02_설계/03_인터페이스_전문설계` |
| 프로그램 목록(프로그램 ID 대장) | 02 6장 | `02_설계/04_화면_프로그램설계/{업무}` |
| 화면설계서 | 04 6장 | `02_설계/04_화면_프로그램설계/{업무}` |
| API 대장 | 02 4.7 | `02_설계/04_화면_프로그램설계/{업무}` (프로그램목록에 포함 가능) |
| 메시지(에러) 코드 대장 | 04 5장 | `02_설계/02_데이터_DB설계` (코드정의서에 포함) |
| DDL/DML 스크립트 | 04 2장 | `03_개발/01_DB_스크립트` |
| 코드 리뷰·정적분석 결과 | 06 | `03_개발/03_코드인스펙션` |
