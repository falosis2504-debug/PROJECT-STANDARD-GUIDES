# 04. 설계 표준

- 상태: 초안 | 버전: 0.1
- 선행: 01, 02

## 목표
DB·API·공통코드·에러코드·화면 설계 산출물의 작성 기준을 정한다.

## 작성 항목
### 1. DB 설계
- 정규화 기준, 논리/물리 모델 산출물 관리
- 데이터 타입 표준 (문자/숫자/일시/여부)
- 필수 공통 컬럼, 논리 삭제 정책
- 인덱스 설계 기준, 마이그레이션 도구 [결정 필요]

### 2. API 설계
- HTTP 메서드는 `GET`/`POST` 만 사용하며 동작은 기능명 동사로 표현 (02-naming-convention 4장). RESTful 리소스 설계는 적용하지 않음
- HTTP 상태코드 사용 기준 [결정 필요]
- 요청/응답 공통 포맷
  ```json
  { "success": true, "code": "OK", "message": "", "data": {} }
  ```
- 페이징/정렬/필터 파라미터 규칙
- 인증/인가, 멱등성, 버저닝, 문서화(OpenAPI) [결정 필요]

### 3. 공통코드
- 그룹/코드 체계, 관리 테이블, 캐싱 방식

### 4. 에러/메시지 코드
| 구분 | 범위 | 예시 |
|---|---|---|
| 공통 | | |
| 업무별 | | |
- 다국어 메시지 관리 방식

### 5. 화면 설계
- 화면 레이아웃 공통 요소, 입력 검증 표시, 버튼 배치
- 화면설계서 템플릿 항목

### 6. 인터페이스(연계) 설계
- 연계 방식(API/배치/MQ), 전문 구조, 재처리·장애 대응
