# 02-3. 인터페이스 ID 명명규칙

- 상태: **확정** | 버전: 1.1
- 상위 문서: [02-naming-convention.md](02-naming-convention.md) 6장
- **인터페이스는 본 프로젝트의 소스 코드 체계(시스템코드·기능코드·접두부 9자)와 별개의 독립된 체계(별개의 시스템)로 관리한다.** 인터페이스의 업무코드(3자리)와 기능코드(2자리)는 서로 무관하며 매핑하지 않는다. 에러/메시지 코드도 인터페이스 ID 와 별개로 관리한다. (04 5장)
- 🔒 고정 / ✏️ 가변(프로젝트별 정의) / `[결정 필요]` 미결정
- 아래 시스템·업무 코드 값은 **은행권 SI 사례(예시)** 이며, 신규 프로젝트에서는 ✏️ 표를 해당 프로젝트 값으로 교체한다.

## 1. 기본 원칙 🔒
1. **고정 길이**: 구분자(`_`) 없이 **총 16자리 고정 길이**로 구성한다. (전문 헤더 고정 바이트 파싱, 연계 라우팅 표준화)
2. **문자 규칙**: 영문 대문자(`A-Z`)와 숫자(`0-9`)만 사용한다.
3. **DB 컬럼**: 자릿수 확장 대비 `IF_ID VARCHAR2(20)` 으로 정의한다.
4. **중앙 통제 채번**: 개발자 임의 채번 금지. 연계 아키텍트(TA) 또는 통합 메타 관리를 통해서만 발급한다.
5. **결번 유지(재사용 금지)**: 설계 변경으로 폐기된 ID 는 상태를 `폐기`로 관리하고 영구 보존하며 다른 기능에 재사용하지 않는다.

## 2. 명명 패턴 (16자리) 🔒
```
IF + [송신시스템(3)] + [수신시스템(3)] + [처리유형(1)] + [업무코드(3)] + [일련번호(4)]
예) IFMBKCORSLON0001
```
| 순서 | 위치 | 항목 | 길이 | 코드 규칙 | 설명 |
|---|---|---|---|---|---|
| 1 | 1~2 | 접두어 | 2 | `IF` | Interface 식별 고정 문자 |
| 2 | 3~5 | 송신시스템 | 3 | 영문 대문자 3자리 | 최초 요청(Request)을 발송하는 주체 시스템 |
| 3 | 6~8 | 수신시스템 | 3 | 영문 대문자 3자리 | 요청을 받아 처리(Response)하는 대상 시스템 |
| 4 | 9 | 처리유형 | 1 | `S`, `A`, `B`, `F` | 동기/비동기/배치/파일 연동 방식 |
| 5 | 10~12 | 업무코드 | 3 | 영문 대문자 3자리 | 업무 분류 코드 |
| 6 | 13~16 | 일련번호 | 4 | `0001`~`9999` | 동일 송수신·유형·업무 내 기능(API/전문) 고유 순번 |

예: `IFMBKCORSLON0001` = 모바일뱅킹 → 계정계 / 동기 / 여신업무 / 0001번

### 3.2 처리 유형 코드 (1자리) 🔒
| 코드 | 유형 | 설명 |
|---|---|---|
| `S` | Sync (실시간 동기) | 요청 후 응답을 즉시 대기하는 API/전문 거래 (조회, 이체 등) |
| `A` | Async / MQ (실시간 비동기) | 메시지 큐 기반 비동기 전송 (푸시/알림톡 발송, 후행 로그 적재) |
| `B` | Batch DB (배치 연동) | 대량 데이터 DB-to-DB 또는 ETL 정기 이관 |
| `F` | File / SFTP (파일 전송) | 대용량 정산 파일, 고시환율, 기관 배치 파일 송수신 |

### 3.3 업무 구분 코드 (3자리) ✏️
| 코드 | 업무명 | 코드 | 업무명 | 코드 | 업무명 |
|---|---|---|---|---|---|
| `COM` | 공통/인증 | `DEP` | 수신 | `FEX` | 외환 |
| `CST` | 고객 | `LON` | 여신 | `TRN` | 계정/이체 |
| `ACT` | 회계/결산 | `CRD` | 카드 | `MKT` | 마케팅/알림 |

- **업무코드(3자리)와 5.3 기능코드(2자리)는 별개로 사용한다.** 파일·URL·DB 는 기능코드 2자리, 인터페이스 ID 는 업무코드 3자리를 쓰며 서로 매핑하지 않는다. 🔒

## 4. 대량 인터페이스 관리 규칙
### 4.1 일련번호 대역(Block) 할당 🔒
일련번호 4자리를 세부 모듈 대역으로 분할하여 충돌 없이 채번한다.
| 대역 | 용도 (예: 여신) |
|---|---|
| `0001 ~ 0999` | 해당 업무 공통 / 기준정보 |
| `1001 ~ 1999` | 세부 모듈 1 (개인신용대출) |
| `2001 ~ 2999` | 세부 모듈 2 (주택담보대출) |
| `3001 ~ 3999` | 세부 모듈 3 (기업여신) |
| `4001 ~ 4999` | 세부 모듈 4 (연체/사후관리) |
| `9001 ~ 9999` | 대외기관 특수 연계 및 마이그레이션 임시용 |
- 모듈 대역의 의미는 업무별로 프로젝트에서 정의한다. ✏️
- 이 일련번호 대역 체계는 **인터페이스 ID 전용**이며, 프로그램 ID 의 일련번호(상위 2자리 중분류 + 하위 2자리, 02 5.1.1)와는 별개이다.

### 4.2 양방향 및 다중 연계 기준 🔒
1. **동기식(`S`) 1개 ID 원칙**: 요청과 응답을 한 트랜잭션으로 묶어 **최초 요청을 발송하는 시스템을 송신시스템**으로 지정하고 ID 1개만 부여한다.
2. **비동기 콜백 분리**: 요청 후 별도 세션으로 역방향 결과를 수신하는 거래는 정방향·역방향 ID 를 각각 발급한다.
3. **허브 경유 표기**: EAI/MCI/FEP 등 중계 솔루션을 거치더라도 **최종 업무 출발지와 최종 목적지** 기준으로 송수신 코드를 부여한다. (예: `MBK` → `MCI` → `COR` 이면 `IFMBKCOR...`)

| `IFMBKCORSCST0001` | 모바일뱅킹 → 계정계 | 동기(`S`) | 고객(`CST`) | 고객 기본정보 및 등급 실시간 조회 |

| `IFCORFEPSTRN0001` | 계정계 → 대외계 | 동기(`S`) | 거래(`TRN`) | 금융결제원 타행즉시이체 실행 |
| `IFCORMCIAACT0001` | 계정계 → 채널허브 | 비동기(`A`) | 계정(`ACT`) | 입출금 거래내역 실시간 푸시 발송 |
