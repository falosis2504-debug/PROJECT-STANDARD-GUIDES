# 05. 형상관리 및 릴리스

- 상태: 초안 | 버전: 0.1

## 목표
브랜치·커밋·리뷰·배포 절차를 확정한다.

## 작성 항목
### 1. 브랜치 전략 [결정 필요]
| 브랜치 | 용도 | 생성 원본 | 병합 대상 |
|---|---|---|---|
| main | 운영 배포본 | | |
| develop | 통합 개발 | | |
| feature/* | 기능 개발 | | |
| release/* | 릴리스 준비 | | |
| hotfix/* | 긴급 수정 | | |
- 브랜치 이름: `feature/{이슈번호}-{kebab-설명}`

### 2. 커밋 메시지
```
<type>(<scope>): <제목 50자 이내>

<본문: 무엇을/왜>

Refs: #이슈번호
```
type: `feat` `fix` `docs` `style` `refactor` `test` `chore` `build` `ci`

### 3. 리뷰/병합 규칙
- PR 필수, 최소 승인 인원, 셀프 병합 금지 여부
- 병합 방식(squash/merge/rebase) [결정 필요]
- PR 템플릿, 리뷰 SLA

### 4. 버전/릴리스
- 버전 규칙(SemVer), 태그 `v1.2.3`
- 릴리스 노트 작성 기준, 변경 이력 관리

### 5. 배포 절차
- 환경별 배포 흐름(dev → stg → prod), 승인자
- 배포 전 체크리스트, 롤백 기준·절차
- CI/CD 파이프라인 단계

### 6. 이슈 관리
- 이슈 유형/우선순위/라벨 체계
